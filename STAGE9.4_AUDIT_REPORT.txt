# 1. EXECUTIVE SUMMARY
========================================================================

The backend is in GOOD SHAPE and is genuinely authoritative. The opportunity /
application system, credits, LiveKit, communication hub, learning subsystem and
the Stage 9.4 notification READ API are all real, JWT-scoped, owner-checked and
terminate in PostgreSQL.

The frontend is BIMODAL, and that is the entire problem.

  ~30 pages are GENUINELY REAL and correctly consume the current API:
    opportunities, opportunity-details, applications (student view), jobs,
    my-learning, messages, requests, credits, profile, dashboard,
    explore-skills, skill-mapping, careerverse, ai-career-coach, sandbox-*,
    learning-player, course-details, discussion-room, live-discussions.

  ~35 pages are PRE-ARCHITECTURE PLACEHOLDERS or PURE DUMMY DATA and still sit
  in production navigation:
    recruiter-dashboard, find-talent, talent-pool, talent-profile, students,
    hiring-analytics, company-profile, interviews, internships, aptitude, dsa,
    interview-prep, community, calendar, create-session, session-room,
    bookmarks, projects, match-waiting, discussion-waiting, tutor-profile, ...

THREE FINDINGS DOMINATE EVERYTHING ELSE:

1. notifications.js IS NOT "WIRED WRONG" -- IT IS A DEAD FILE.
   `node --check` fails at line 1:
       SyntaxError: Unexpected token '==='
   The opening `/*` of the header comment was lost.
   Current file: 241 lines / 6,994 bytes.
   Committed at HEAD: 919 lines / 25,033 bytes.
   The file was TRUNCATED MID-EDIT.
   It also calls SIX functions that no longer exist anywhere in the file:
       updateUnreadCount, addTools, updateEmptyState, addNotificationActions,
       restoreReadState, prepareNotification
   and references THREE undefined variables:
       markReadButton, toast, deletedNotification
   => The browser never executes a single line of it.

2. THERE IS NO notification.js AND NO notification.html.
   Only notifications.js / notifications.html exist.
   Any task written against "notification.js" targets a file that does not exist.

3. THREE MORE JS FILES FAIL TO PARSE; two are ACTIVELY LOADED by real pages:
       stage6-projects.js       -> loaded by projects.html       (BROKEN)
       stage6-career-report.js  -> loaded by career-report.html  (BROKEN)
       profile_fixed.js         -> orphaned, never loaded        (BROKEN)

Additionally: THE RECRUITER APPLICATION-REVIEW PAGE THAT THE SIDEBAR LINKS TO
(applications.html?role=recruiter) IS 100% HARDCODED DUMMY DATA -- even though a
real, complete recruiter review workflow now exists in jobs.html.
applications.js line 149 explicitly returns early for the recruiter view.

VERDICT

  No public applicant data leaks email.
